# 设计约束清单

生成日报 HTML 前先过一遍这张表。它的作用不是"教你审美"，而是**替你排除绝大多数会变丑的选项**——排掉廉价的做法，剩下的自然就有设计感。

> 来源：[@op7418 的设计 Skill 方法论](https://x.com/op7418/status/2065232309310427565) + 本项目的实践修正。
> 核心判断：**好看不是玄学，而是可拆解、可编码、可检查的行业常识。**

---

## 一、反模式：模型默认会收敛到的平庸模式

生成式产出的默认审美，几乎必然落到下面这些选项上。**逐条检查，中一条就改掉：**

| 反模式 | 为什么廉价 |
|---|---|
| Tailwind 风大色块 | 无视觉重心，信息密度失控 |
| 紫色 / 多彩渐变 | 最偷懒的"科技感"捷径 |
| emoji 堆砌 | 用符号代替设计 |
| 发光（glow）、大面积 blur | 掩盖层次结构不清 |
| 过度圆角（大 pill、圆角卡片满天飞） | 2015 年的移动端遗风 |
| 无意义的动效 | 动效应该是信息，不是装饰 |
| 纯白 `#fff` / 纯黑 `#000` | 刺眼、廉价 |
| 信息密度失控 | 什么都想说 = 什么都没说清 |
| 用 `Inter` 一类中性无衬线承担全部层级 | 没有字重/字体对比，等于没有排版 |

## 二、正面约束（可直接当验收标准）

1. **不使用纯白和纯黑。** 用带色调的近白 / 近黑。
2. **不让用户任意输入 hex。** 只提供经过验证的主题色板。
3. **不用紫色多彩渐变、发光、大面积 blur 作为主视觉捷径。**
4. **动画只在必要时使用，且只动 `transform` / `opacity`。**
   颜色和 `box-shadow` 的 hover 过渡可以，但不要位移整块内容。
5. **图文卡片优先真实摄影和截图美化**，AI 生图只作兜底。
6. **版式骨架先被人工验证**，AI 负责填充、组合和微调——
   把 AI 的任务从"自由设计"降级成"在高质量骨架里填充"。
7. **文字必须自适应**：根据图像主体、明度和可读区域决定落点、字色、遮罩和断行。

### 单色相原则

**一个页面只允许一个主色相**，辅色和中性色服务于它。
"有主色调"不等于"到处都是颜色"——而是**让同一个颜色以不同形式反复出现**：
实心底、描边、细线、巨型淡色字符、正文高亮。

## 三、本项目配色规范

### 主色板

```css
--paper:#f8f9fc;          /* 冷白底（不是纯白） */
--ink:#0e1526;            /* 带蓝调的黑（不是纯黑） */
--ink-2:#525b70;          /* 次级文字 */
--ink-3:#98a1b5;          /* 三级文字 */
--rule:#e3e7f1;           /* 分隔线 */

--brand:#002fa7;          /* 克莱因蓝 IKB —— 主色 */
--brand-deep:#001e6b;
--brand-soft:#e6ebf7;
--brand-tint:#f2f5fc;

--yellow:#ffd400;         /* 黄 —— 只做底和高亮 */
--yellow-soft:#fff6cc;
--yellow-deep:#8a6a00;    /* 黄色系文字用这个，不是纯黄 */

--neutral-ink:#8a93a6;    /* 第三档标签的中性色 */
```

### 黄不做文字色（硬规则）

亮黄放在浅底上当字，对比度只有约 **1.3:1**，等于自残。
**黄色只走"底"和"高亮"**：

- 页面顶部双色条（6px 蓝 + 3px 黄）
- TOP3 标题下的 3px 黄线
- TOP3 标签底色
- 正文 `<b>` 的黄色马克笔高亮

需要黄色系文字时，降到 `--yellow-deep:#8a6a00`。

### 三档价值标签

| 类名 | 含义 | 样式 |
|---|---|---|
| `p-hot` | 高价值 | 主色实心 + 白字 |
| `p-warm` | 需注意 | 淡黄底 + 深黄字 |
| `p-cool` | 可复现 | 白底 + 灰蓝描边 |

卡片左侧编号的颜色**跟随该卡的价值标签**（用 CSS `:has()` 实现，不需要额外 class）：

```css
.card:has(.p-hot)::before{color:var(--brand)}
.card:has(.p-warm)::before{color:#b8912a}
.card:has(.p-cool)::before{color:var(--neutral-ink)}
```

## 四、排版规范

- **字号跳跃要明确。** 40px 标题 / 20px 组标题 / 15px 卡片标题 / 13.5px 正文，
  层级差距足够大才不会糊成一团。
- **衬线体只给数字和英文。** `Georgia` 负责所有大数字、序号、巨型编号——
  这是"编辑感"最省力的来源。中文标题保持无衬线，保证清晰度。
- **卡片编号用 CSS counter 自动生成**，不写进正文 HTML：
  ```css
  .wrap{counter-reset:cardn}
  .card{counter-increment:cardn}
  .card::before{content:counter(cardn,decimal-leading-zero)}
  ```
- **圆角一律 0。** 这套风格不用圆角。
- **阴影一律去掉。** 用 1px 细线分隔，不用 box-shadow 堆层次。
  唯一的例外是 hover 时的 `inset` 细线，它不引起布局跳动。

## 五、交付前设计自查

```sh
f=<产出文件>.html
grep -c 'radial-gradient' $f          # 应为 0
grep -ciE '#(8b5cf6|a855f7|7c3aed)' $f # 应为 0（紫色渐变）
grep -c 'border-radius: *[1-9]' $f     # 应为 0（除极小的 2px）
grep -c 'box-shadow' $f                # 只应有 hover 的 inset 规则
```

再确认三件事：

1. **主色是否以多种形式反复出现**（实心、描边、细线、淡色大字）——
   只有一两处点缀，等于没有主色调。
2. **有没有任何一处颜色是"随手加的"**——每个颜色都应该能追溯到上面的色板。
3. **去掉所有颜色后，版式是否依然立得住**——如果拿掉颜色就散了，
   说明结构没做够，颜色在替结构干活。
